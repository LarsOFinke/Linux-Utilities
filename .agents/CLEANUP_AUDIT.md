# Repository cleanup audit

Reviewed the 246 initially tracked files across the root and 11 modules by file type, ownership directory, line count, entry point, and installation/portability contract. Line count alone does not determine whether a file should be split. This audit records the current boundaries and the remaining candidates so future changes start with an owner and a test.

| Area | File assessment | Cleanup decision |
| --- | --- | --- |
| Root scripts, `configuration/`, `scripts/`, `.github/`, and root docs | Entry points, catalog, verification, and guidance each have a distinct role. | `main.sh` owns interactive action selection; `scripts/` owns setup, update, uninstall, and cache cleanup. Catalog and guides describe the root layout. |
| `installer/` | Former `manage.py` mixed registry, file operations, build, setup, update, uninstall, and CLI behavior (588 lines); former `catalog.py` mixed validation and menu selection (305 lines), with a large `load_catalog()` method. Root selectors mixed UI with lifecycle dispatch; remote deployment mixed SSH snippets, records, and transport. | Moved the wrapper to root `installer/`, split its validators and lifecycles, and kept `main.py` as the transaction entry point. Setup planning and optional post-install configuration have their own files; uninstall planning, hooks, and removal are separate. Remote bootstrap and state scan now have individual files under `remote/scripts/`. Root `main.sh` selects action scripts in `scripts/`. |
| `data-privacy/backup` and `data-privacy/privacy` | Snapshot/remote and policy/schedule/workflow scripts already have separate owners. Backup had two byte-identical command sources. | Point both backup command names to one source file; keep distinct installed command names. |
| `monitoring/network` | Capture command owns one profile lifecycle; `capture_registry.py` owns persistent capture state. | Keep together to preserve one lock and one command interface. |
| `monitoring/log-scout` | Source, scan, rules, view, cache, and CLI are already separated. The 300-line `LogScoutTest.py` covers multiple behaviors but is test code. | Keep production boundaries; split test cases only when a new fixture or feature makes an independent suite useful. |
| `monitoring/canary` | C tracker separates app, config, events, monitoring, process lookup, action, and output; Python tools and templates have their own directories. | Keep the existing concern boundaries. Avoid splitting C implementation files merely for their length. |
| `system-utilities/system` | Components separate AMD gaming from H848 audio. The 285-line H848 install script included package setup, backups, and three inline output templates. | Extracted the WirePlumber and systemd templates into manifest-owned companion files. The remaining setup flow and backup helper are cohesive enough to keep together. |
| `system-utilities/termlay` and `system-utilities/connect-vps` | Storage models/classes, terminal/process integration, prompts, SSH, and CLI are already separated. | Keep current boundaries. |
| `server-services/system-update` and `server-services/ubuntu-updates` | Manual updating is a separate module; automatic-update policy, state, actions, and workflow are distinct scripts. | Keep current boundaries. |
| `server-services/vps-gateway` | Core/site shell workflows, site model/ports, initiation, deployment, and generator are separate. The 337-line gateway shell test spans several user workflows. | Split first-run site choice and layout validation from gateway mutation. Keep the 337-line shell integration test together because it shares one temporary fake host and exercises the complete wizard and deployment lifecycle. |
| Portable installer and module entry points | Each former 307-line `portable_module.py` mixed scope locking, file safety, state, component selection, hooks, install, removal, and CLI. Eleven copied helpers and support packages bloated the module trees; 22 module shell wrappers repeated routing logic. | Keep one canonical entry point and `portable_support/{state,files,hooks,install_plan,install,uninstall}.py` under `installer/portable/`. SSH archives include the helper temporarily. Module setup/uninstall paths link to `installer/module_entry.sh`; module directories alone no longer install themselves. |

For any future split, first identify a stable responsibility and its callers. Preserve command names, registry ownership, scope locking, rollback, and SSH bundle behavior. Add companion files to manifests when installed scripts import or source them. Run `python3 installer/verify.py` after lifecycle changes; it checks shell syntax, ShellCheck, transactions, recovery, portability, and module suites without live host operations.

Installer tests are grouped in `installer/tests/{catalog,lifecycle,portable,remote,ui}/`. Canary's multi-concern suite is grouped in `tests/{lifecycle,tracker,tools}/`. Single-file module test directories stay flat until they gain a second independent concern. The verifier discovers nested test scripts, so these boundaries do not drop coverage.
