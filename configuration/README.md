# Installation catalog

[`install.json`](install.json) lists module manifest paths and the shared user/system command and registry locations. The root selector reads each `src/<module>/module.json` to show its display name and category. The stable `id` is the value passed to `--module`; changing a display name or category does not rename commands or registry entries.

Each module manifest owns its commands, source paths, setup and documentation paths, examples, optional inactive cron template, supported `scopes`, build script, and lifecycle hooks. Paths for source files are relative to the module directory. `build_commands` maps an installed command name to a module script that accepts one output path. `post_install` describes an optional interactive configuration prompt. `pre_remove` names an installed command and arguments used to clean up module-owned state before its binaries are removed. The root installer verifies the installed removal hook's hash before running it. `runtime_configs` and `schedules` describe paths in the registry; the module creates and cleans up those files.

Keep host-specific settings inside each module's own `.env` or `.cfg` file, outside the repository. The root catalog contains installation metadata only. The root installer uses one transaction and registry for same-scope selections. A copied module directory uses its `setup.sh`, `uninstall.sh`, `module.json`, and bundled `portable_module.py`; it writes a separate registry under `shell-scripts/portable/` and refuses to replace a command owned by the root installer or another module.

Edit `install.json` when adding or removing a module or changing shared install locations. Edit that module's `module.json` when changing its commands, build, examples, scope, display name, category, or removal hook. Run `python3 src/installation/tests/portable_modules_test.py` to check copied modules. Before changing an installed command name, plan for the old name to be removed on reinstall and update callers and environment variables.
