# Installation catalog

[`install.json`](install.json) lists module manifest paths and the shared user/system command and registry locations. The root selector reads each `src/<concern>/<module>/module.json` to show its display name, category, and subcategory. The stable `id` is the value passed to `--module`; changing a presentation label does not rename commands or registry entries.

Each module manifest owns its category, subcategory, commands, source paths, setup and documentation paths, examples, optional inactive cron template, supported `scopes`, build script, and lifecycle hooks. Paths for source files are relative to the module directory. `build_commands` maps an installed command name to a module script that accepts one output path. `post_install` describes an optional interactive configuration prompt. `pre_remove` names an installed command and arguments used to clean up module-owned state before its binaries are removed. The root installer verifies the installed removal hook's hash before running it. `runtime_configs` and `schedules` describe paths in the registry; the module creates and cleans up those files.

An optional `components` map gives each component a description and a disjoint list of command names. Together, the lists must cover every command in the module. Modules with components cannot use module-wide cron or lifecycle hooks. The root commands accept `--component MODULE:NAME`; the temporary SSH helper receives local component names. Component selection is additive on install and selective on uninstall.

Keep host-specific settings inside each module's own `.env` or `.cfg` file, outside the repository. The root catalog contains installation metadata only. The root installer uses one transaction and registry for same-scope selections. A module directory needs the repository installer for local setup and removal. SSH deployment bundles the canonical `installer/portable/` helper with one module in a temporary archive; it writes separate state under `shell-scripts/portable/` and refuses to replace an unmanaged command.

Edit `install.json` when adding or removing a module or changing shared install locations. Edit that module's `module.json` when changing its commands, build, examples, scope, display name, category, subcategory, or removal hook. The validators for these fields live in `installer/catalog/`; update the matching validator and `installer/tests/catalog/catalog_test.py` when changing the schema. Run `python3 installer/tests/portable/portable_modules_test.py` to check temporary SSH bundles. Before changing an installed command name, plan for the old name to be removed on reinstall and update callers and environment variables.
